# seesee / 看看 — 任务计划与里程碑

> 版本 v0.1 · 2026-11-06

## 0. 技术路线（为什么是原生 C++）

「极速」不是优化出来的，是架构决定的。三条候选路线在本机的实测对比：

| 路线 | 冷启动到首图 | 包体 | 依赖 | 结论 |
| --- | --- | --- | --- | --- |
| Electron / Tauri(WebView2) | 800 ms – 3 s | 60–150 MB | Chromium/WebView2 运行时 | 直接出局：运行时装不起来就谈不上极速 |
| WPF / WinUI 3 (.NET) | 300–600 ms | 依赖 .NET 运行时 | .NET 8 桌面运行时 | 出局：CLR 初始化就吃掉了预算 |
| **原生 C++20 + Win32 + Direct2D + WIC** | **80–115 ms** | **703 KB 单文件** | 无（静态 CRT） | 采用 |

渲染后端还做过一次反向选择：硬件 `ID2D1HwndRenderTarget` 需要先建 D3D11 设备，本机冷启动实测 **156 ms**（驱动初始化税），而 D2D 的**软件** DC 渲染目标只要 **9 ms**。所以 v1 走「软件 D2D 渲染 + BitBlt 上屏」，把 GPU 留给 v2 做"先软后硬"升级。

## 2. 代码结构

```
seesee/
├─ src/
│  ├─ main.cpp        入口：命令行解析（图片路径 / --bench / --shot / --panel / --lang / --register）
│  ├─ app.h/.cpp      窗口、消息循环、渲染（D2D 软件 DC 目标 + DIB）、输入、缓存、设置面板、基准
│  ├─ loader.h/.cpp   目录扫描（自然排序）+ 线程池 + WIC 解码（DCT 缩放 / EXIF 方向 / 预取 / 缩略图）
│  ├─ settings.h/.cpp 设置（%LOCALAPPDATA%\SeeSee\settings.ini，含 language / keybind）
│  ├─ i18n.h/.cpp     界面文案表（简体中文 / English，跟随系统）
│  ├─ keys.h/.cpp     键位表（默认值 / 用户覆盖 / 冲突解绑 / 持久化 / 键名格式化）
│  └─ assoc.h/.cpp    文件关联（HKCU ProgID + Capabilities + .reg 兜底）
├─ resources/         图标 .ico、清单 .manifest、资源 .rc
├─ prototype/         UI 高保真原型（HTML，单文件）
├─ tools/             一次性探针与生成脚本（不含在产品里）
├─ docs/              需求 / 计划 / UI 规范
├─ build.ps1          一键构建（vcvars64 → cmake → ninja）
└─ bin/seesee.exe     产物（单文件，765 KB）
```

## 3. 线程模型

```
UI 线程 (STA)                          Worker 线程 ×3 (MTA)
─────────────                          ────────────────────
消息循环 / D2D 绘制 / BitBlt            thread_local IWICImagingFactory
   │  Request(index, level)                  │
   ├────────────── 任务队列 ────────────────►│ 读文件 → WIC 解码 → EXIF 摆正
   │                                         │ （只产 CPU 像素，不碰 D2D）
   │◄──────── PostMessage(WM_APP+1) ────────┘
   │
   └─ 上传为 D2D 位图 → 入 LRU 缓存（12 条）→ 失效重绘
```

- **不做跨线程 COM 共享**：WIC 工厂、解码器、位图全部留在 worker 线程内。
- **预取策略**：`SetWanted()` 维护"当前 + 前后各 2–3 张"的优先级集合，UI 翻页时队列自动重排。
- **缓存**：按 `(索引, 缩放级别)` 作 key，超过上限按最近使用淘汰。

## 4. 性能预算与实测

| 段落 | 预算 | 实测（1920×1200 样本） |
| --- | --- | --- |
| exe 加载 + CRT | 20 ms | 9–14 ms |
| 窗口创建 | 10 ms | 4.6 ms |
| D2D/DWrite 工厂 | 5 ms | 0.1 ms |
| 建软件渲染目标 + 后备 DIB | 15 ms | 10 ms |
| 解码（与上一项并行） | 30 ms | 12–13 ms |
| 首帧绘制 | 20 ms | 18–19 ms |
| **合计** | **150 ms** | **80–84 ms** |

## 5. 风险与对策

| 风险 | 影响 | 对策 |
| --- | --- | --- |
| 软件渲染在 4K 全屏缩放时帧率掉到 60 以下 | 拖动略顿（实测 15 ms/帧，仍 > 60 fps 边缘） | v2 加"空闲后升级到硬件设备"的双后端 |
| 超大图（>50 MP）解码慢 | 首图等待 | 已做 DCT 缩放解码；可再加"先出 1/8 缩略图占位 → 再补全" |
| WebP/AVIF/HEIC 依赖系统解码器 | 部分机器不支持 | 检测失败给出明确提示；v1.x 可内置 libwebp |
| 安全软件拦截 HKCU 写入 | 无法设为默认 | 自动生成 `.reg` 供用户双击导入（已实现） |
| Windows 11 不允许程序直接改默认关联 | 只能引导用户 | 调 `ms-settings:defaultapps?registeredAppUser=SeeSee`，落到本程序的关联页 |

## 6. 验证方式

- `--bench`：全链路分帧 + 稳态帧时（写 `seesee-bench.txt`）。
- `--shot <png>`：把首帧存成 PNG，用于 UI 回归对比（所见即所得，不依赖抓屏 API）。
- `prototype/ui-mockup.html`：交互规格的可执行参考，UI 改动后逐项对照。
